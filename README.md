# masker

[![CI](https://github.com/qwaseri832/masker/actions/workflows/ci.yml/badge.svg)](https://github.com/qwaseri832/masker/actions/workflows/ci.yml)
[![Go](https://img.shields.io/badge/Go-1.24-00ADD8?logo=go&logoColor=white)](https://go.dev/)

CLI-утилита, которая заменяет цифры в тексте на `*`. Работает потоком: память
не зависит от размера файла.

```
$ masker -i testdata/input.txt
Привет ***
Мой телефон ***********
Год ****
Ещё строка без цифр
```

## Установка

```bash
go install github.com/qwaseri832/masker/cmd/masker@latest
```

## Использование

По умолчанию читает stdin и пишет в stdout, поэтому встраивается в конвейер:

```bash
cat access.log | masker | grep ERROR
```

Файлы задаются флагами:

```bash
masker -i input.txt -o output.txt
```

| Флаг | По умолчанию | Описание |
|---|---|---|
| `-i` | `-` | входной файл, `-` — stdin |
| `-o` | `-` | выходной файл, `-` — stdout |
| `-log-level` | `info` | `debug`, `info`, `warn`, `error` |

Логи пишутся в **stderr**, чтобы не смешиваться с данными в stdout.

Выходной файл пишется через временный файл рядом с целевым и переименовывается
только после успешной обработки. Если процесс прервать на середине, прежний
файл останется нетронутым, а недописанного мусора не появится.

Остановка по `Ctrl+C` — код возврата 130.

## Устройство

```
cmd/masker        разбор флагов, файлы, сигналы, коды возврата
internal/mask     правило замены: интерфейс Masker и реализация Digits
internal/pipeline построчный прогон io.Reader → Masker → io.Writer
```

Точка расширения ровно одна — интерфейс `Masker`:

```go
type Masker interface {
	Mask(line string) string
}
```

Чтобы маскировать не цифры, а, например, адреса почты, нужна только новая
реализация: чтение, запись, обработка ошибок и сигналов остаются прежними.
Источник и приёмник специального интерфейса не требуют — эту роль играют
`io.Reader` и `io.Writer`, что заодно делает `pipeline.Run` тестируемым
через `strings.Reader` и `bytes.Buffer`, без моков.

### Почему без пула горутин

Замена цифры в строке занимает несколько наносекунд, а отправка в канал и
переключение горутины — десятки. Пул воркеров потратил бы на диспетчеризацию
больше, чем на саму работу, и вдобавок потребовал бы держать весь файл в
памяти, чтобы собрать результат обратно по индексам. Последовательный проход
по потоку и быстрее, и не ограничен размером файла.

Параллелить здесь имело бы смысл, будь обработка строки дорогой — например,
при сетевом запросе на каждую строку.
